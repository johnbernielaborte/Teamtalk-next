# 01. Архитектура и принципы работы

Система плагинов TeamTalk Next построена на базе штатного механизма динамической загрузки кода Android ART/Dalvik с помощью `dalvik.system.DexClassLoader`.

---

## 🏛 Общая схема работы

```
                ┌────────────────────────────────────────────────────────┐
                │                  TeamTalk Next Client                  │
                │  - MainActivity                                        │
                │  - TeamTalkService (служба фонового соединения)        │
                │  - TeamTalkBase (C++ JNI SDK ядро)                     │
                └───────────────────────────┬────────────────────────────┘
                                            │
                                            ▼
                ┌────────────────────────────────────────────────────────┐
```

## 🔄 Жизненный цикл плагина

Каждый плагин проходит 4 четких этапа жизненного цикла:

```
[Обнаружение файла .jar/.dex]
           │
           ▼
        onLoad()        ───► Регистрация команд, слушателей, инициализация данных
           │
           ▼
       onEnable()       ───► Плагин активирован, события начинают поступать
           │ ◄──┐
           │    │ (Пользователь переключает тумблер в интерфейсе)
           ▼    │
      onDisable()       ───► Плагин деактивирован, события и команды приостановлены
           │
           ▼
       onUnload()       ───► Очистка ресурсов, освобождение дескрипторов
```

1. **`onLoad(PluginContext context)`**:
   * Вызывается однократно при загрузке плагина в оперативную память.
   * Плагин получает объект `PluginContext`, содержащий ссылки на сервис TeamTalk, JNI SDK, файловое хранилище плагина и логгер.
   * Здесь регистрируются команды чата (`registerCommand`) и слушатели событий (`registerEventListener`).

2. **`onEnable()`**:
   * Вызывается, когда плагин активируется пользователем или включается автоматически при старте.
   * В этот момент плагин становится активным и начинает получать сетевые и пользовательские события.

3. **`onDisable()`**:
   * Вызывается при отключении плагина пользователем.
   * События прекращают поступать в данный плагин, а его слэш-команды временно отключаются.

4. **`onUnload()`**:
   * Вызывается перед полным удалением плагина или перезагрузкой системы плагинов.
   * Здесь необходимо закрыть открытые потоки, сокеты, таймеры и освободить память.

## 🛡 Изоляция и отказоустойчивость (Safe Sandbox)

* **Защита от сбоев (Crash Guard):**  
  Все вызовы методов плагина (`onLoad`, `onEnable`, `onTextMessageReceived` и др.) обёрнуты в блоки `try-catch (Throwable t)`. Если сторонний плагин выбросит `NullPointerException` или любую другую ошибку, она будет залогирована в `PluginLogger`, статус плагина перейдёт в `Error`, но само приложение **TeamTalk Next продолжит работать стабильно**.
* **Изолированное хранилище данных:**  
  Метод `context.getDataFolder()` предоставляет плагину индивидуальную директорию в защищенном хранилище приложения (`/data/data/org.nekit.ttproplus/files/plugins/<plugin_id>_data/`).
* **Изолированные настройки:**  
  Метод `context.getPreferences()` возвращает отдельный файл `SharedPreferences` для данного плагина (`plugin_<plugin_id>.xml`), не конфликтующий с общими настройками TeamTalk.
